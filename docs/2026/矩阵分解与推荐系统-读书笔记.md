## 为什么是矩阵分解

评分矩阵里已知项往往不到 1%。矩阵分解把用户和物品各映射到一个低维空间，用内积去补未知项：

```
r_hat(u,i) = mu + b_u + b_i + p_u^T q_i
```

其中 `mu` 是全局均值，`b_u`、`b_i` 是用户与物品偏置——**先扣掉「这个人本来就爱打高分」和「这个物品本来就受欢迎」**，剩下的才是交互信号。

## 目标函数与求解

```
min  sum over (u,i) in K  ( r_ui - r_hat(u,i) )^2
       + lambda * ( ||p_u||^2 + ||q_i||^2 + b_u^2 + b_i^2 )
```

只对已知项求和（`K` 是观测集合），两种常见解法：

| 方法 | 每次迭代 | 适合 |
|---|---|---|
| SGD | 扫一个评分更新一次，`O(|K| d)` | 数据大、要实时增量 |
| ALS | 交替固定一侧解线性系统 | 能并行、隐式反馈更顺 |

## 隐式反馈：置信度加权

点击、浏览这类行为没有「不喜欢」的样本。经典做法是把它当**置信度**而不是分数：

```
c_ui = 1 + alpha * r_ui
min  sum over all (u,i)  c_ui * ( p_ui - p_u^T q_i )^2 + lambda * (...)
```

`r_ui` 是行为强度（次数、时长），`p_ui` 是 0/1 偏好。全矩阵参与求和，但 ALS 的坐标解可以写成只依赖非零项的形式，所以并没有真的遍历整个 `m × n` —— 说「ALS 太慢」的，多半是没做这个化简。

```python
# ALS 的一步用户侧更新（伪代码）
# A = Q^T Q ; 逐用户改成 A + Q^T (C_u - I) Q
for u in range(n_users):
    idx = seen[u]                       # 该用户有行为的物品
    Cu  = alpha * weights[u]            # 置信度增量
    A   = Q[idx].T @ (Q[idx] * Cu[:, None]) + Q.T @ Q + lam * np.eye(d)
    b   = Q[idx].T @ (Cu * pref[u])
    P[u] = np.linalg.solve(A, b)
```

## 评估口径的坑

- **RMSE 好看 ≠ 推荐好用**：评分预测是回归目标，排序才是推荐目标，两者排序不一致
- 离线评估只看**留出的已知项**，等于假装未知项是负样本，和线上分布差得远
- 排序指标用 Precision@K / NDCG@K，都要**每用户独立留出**，别全局随机切
- 冷启动用户只有偏置项可学，早停和正则要比常规更狠

> 结论：把偏置和正则先调明白，再谈更高阶的模型；很多「深度模型涨点」其实是基线没调好。
