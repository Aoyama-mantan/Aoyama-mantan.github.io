文档库使用说明

数据只有一个来源

docs/ 目录下的 markdown 是权威数据。每次推送到仓库后，GitHub Actions 会自动：

  1. 把每份 markdown 渲染成站内页面 d/<路径>.html；
  2. 重建首页索引（按日期倒序）与「共 N 份文档」；
  3. 删掉 d/ 下已经没有对应文档的旧页面。

index.html 与 d/ 都是生成物，不用也不该手改。

加一份文档

新建 docs/年份/标题.md，开头写 front matter：

---
title: 矩阵分解与推荐系统 · 读书笔记
type: 笔记
date: 2026-09-28
summary: 一句话摘要，用于页面 description
---

正文正常写 markdown。
字段 作用 省略时
title 索引与文档页的标题 用文件名
type 索引右侧的类型标签 显示「—」
date 索引排序用，YYYY-MM-DD 用文件修改时间
slug 自定义网址路径 沿用 docs/ 下的相对路径
summary 页面 <meta description> 留空
draft 写 true 就不发布 正常发布

几条约定

  • 文件名以 _ 开头、或叫 README.md 的文件不进索引；草稿和说明用这个规则。
  • 图片放 docs/ 里，用相对路径引用（如 ![](img/图.png)），构建时按原路径复制到 d/。
  • 正文里指另一份文档，直接写 [标题](同名.md)，构建时会改写成渲染后的页地址。
  • 类型目前用三类：笔记、论文、项目。

本地先看效果

PY="$LOCALAPPDATA/hermes/hermes-agent/venv/Scripts/python.exe"
"$PY" tools/build_site.py --root .     # 渲染 + 重建索引
"$PY" -m http.server 8931             # 浏览器打开 http://127.0.0.1:8931/

样式与交互一律用 HTTP 验，不要只看 file://——本地直接双击打开的页面，相对路径和脚本行为都可能和线上不一致。
